# HOWTO — using embedded-template in a project repo

## The layout contract

Every project repo created from this template carries the same skeleton:

```
<project>/
├── README.md  LICENSE  CHANGELOG.md
├── CMakeLists.txt  CMakePresets.json
├── .clang-format  .clang-tidy  .cppcheck-suppressions  .clangd
├── .github/workflows/{ci,sitl,hil,release}.yml
├── cmake/                      # toolchain files (copied, then board-pinned)
├── docs/
│   ├── 01-conops.md … 10-eco-log.md
│   ├── 02-srs.md               # the SRS — written BEFORE code
│   ├── 06-rtm.md               # GENERATED by tools/gen_rtm.py, never hand-edited
│   ├── requirements/*.yaml     # source of truth for requirements
│   ├── adr/  reviews/  analysis/  media/
│   └── hardware/               # board fact sheets with provenance
├── hw/                         # PCB projects only (KiCad, fab/, sim/)
├── src/
│   ├── app/  domain/  ports/  bsp/
│   └── adapters/{stm32f4,host,renode}/
├── include/
├── test/{unit,integration,hil}/
├── tools/                      # the RTM/lint/size/sign scripts
└── scripts/{setup-dev,flash}.sh
```

## Bootstrapping a fresh repo

```bash
gh repo create <slug> --template caiobvilar/embedded-template --public --clone
# 1. docs/02-srs.md + docs/requirements/*.yaml  (REQUIRED before code)
python tools/gen_rtm.py check                 # must pass, no requirements yet
# 2. configure CMakePresets.json / arm-none-eabi.cmake for your board
# 3. write src/domain/* (host-testable) first
cmake --preset host-test && ctest --preset host-test
# 4. later: CubeMX -> cubemx/, then src/adapters/stm32f4/
```

## The gates (what "green" means)

| Gate | Command | Fails on |
|---|---|---|
| Unit (host) | `cmake --preset host-test && ctest` | failing assertions |
| Static analysis | `cppcheck --error-exitcode=1 … src/` | warnings (zero-warning policy) |
| Format | `clang-format --dry-run --Werror` | unformatted code |
| Requirements | `python tools/gen_rtm.py --check` | orphan reqs, orphan tests, banned words, bad parents, SRS/RTM mismatch |
| Layering | `python tools/check_layering.py` | `src/domain/` including hardware headers |
| Size budget | `python tools/check_size_budget.py` | flash/RAM over budget |

## Rules that are not optional

1. **Requirements first.** `gen_rtm.py --check` must pass with the SRS in
   place before application code lands.
2. **Domain is pure.** No hardware includes below `src/domain/` — that is
   what makes host testing take milliseconds.
3. **Every measurement ships its raw data + plot script.**
4. **Never hand-edit `docs/06-rtm.md` or `docs/07-test-report.md`** — they
   are generated.
5. **Pin everything.** The toolchain container pins GCC, Renode, Unity, CMock,
   GoogleTest, and Python deps by version + hash.

## Containerised dev

```bash
podman build -t workbench-toolchain -f Containerfile.toolchain .
podman run --rm -it --userns=keep-id -v "$PWD":/w:Z -w /w \
  localhost/workbench-toolchain
```

Rootless Podman only (Fedora); `:Z` relabels for SELinux; `--userns=keep-id`
keeps container-written files owned by your user.
